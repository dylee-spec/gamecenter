# 위클립 발행 가이드 (Claude가 읽는 문서)

위클립은 뷰티 마케터를 위한 주간 트렌드 사이트예요. 예약 자동 발행은 꺼져 있고, 담당자가 채팅에서 "이번 주 위클립 발행해줘"라고 요청할 때만 발행해요.

## 발행 절차
1. 저장소 Actions 탭 → "위클립 데이터 수집" → Run workflow 실행 (1~2분)
2. 끝나면 `work/weeklip/draft.json`에 그 주 데이터가 저장돼요. (사이트에는 아직 안 보임)
3. draft.json을 읽고 아래 규칙대로 글을 다듬어요.
4. 다듬은 호를 `work/weeklip/issues.json` 배열 끝에 추가해 커밋해요. 같은 id가 있으면 교체해요.
5. 1~2분 뒤 https://dylee-spec.github.io/gamecenter/work/weeklip/ 에서 확인해요.

## 이 글의 목적
클라이언트 브랜드(아쿠아픽, 프리메라, 올리브영, 체이싱래빗, 잇츠스킨, 스킨천사, 에스쁘아, 티젠, 바이탈뷰티, 캔메이크, 닥터코스)의 기획자들이 트렌드를 파악하고 기획하는 걸 돕는 글이에요. 가장 중요한 건 두 가지예요.
1. 일반적인 트렌드: 검색 데이터로 확인된 키워드와 업종 무관 유행 포맷
2. 뷰티 업계가 실제로 어떤 광고 소재와 SNS 콘텐츠를 만들고 있는지

## 가장 중요한 원칙: 거짓이 없어야 한다
- 숫자(상승률, 작년 대비, 쇼핑 클릭, 성별·연령 비중, 조회수)는 draft.json 값만 그대로 써요. 반올림·추정 금지.
- draft.json이나 확인한 출처에 없는 사실, 인물, 인용문, 효과는 쓰지 않아요.
- 해석이 들어간 문장(예: 계절 영향으로 보여요)은 "편집부의 해석"이라고 밝혀요.
- 참고 영상이 해외 영상이면 해외 영상이라고 밝혀요.
- **설명·해설 영상은 레퍼런스로 넣지 않아요.** (뉴스, 유래 설명, 뜻 풀이, 사용법 강의 등) 설명은 본문이 맡고, 레퍼런스는 트렌드를 실제로 보여주는 콘텐츠(크리에이터·브랜드의 실제 게시물)만 실어요.
- **'이번 주 트렌드'라는 근거가 있어야 해요.** 옛날 영상이 많아도 최근 한 주 동안 실제로 뜨고 있는지 확인하고, 그렇게 판단한 근거를 본문에 적어요. 근거가 약하면 싣지 않거나, "꾸준히 쓰이는 포맷"처럼 사실대로 표현해요.
- 화장품 광고 금지 표현을 쓰지 않아요: 치료, 치유, 완치, 재생, 처방, 특효, 즉효, 부작용 없음, 기적, 영구적, 의학적, 질병, 주름 제거, 흉터 제거 등. 효능을 단정하지 않아요.

## 글 구조와 문체
- 해요체, 친근하고 술술 읽히게. 박스 나열이 아니라 블로그 글처럼.
- `headline`: 이번 주 핵심을 2줄로 (\n으로 줄바꿈)
- `intro`: 이번 호 소개 3~4문장. 데이터 기간과 선정 기준(직전 4주 평균 대비 +30%)을 밝혀요.
- 트렌드 개수는 고정이 아니에요. 기준(+30%)을 넘은 게 많으면 중요한 순서로 최대 7개, 적으면 2~3개만 실어도 돼요.
- 트렌드마다 `t`(제목), `body`(2~3문단, 중요한 부분은 <b>로 강조), `ideas`(활용 제안 2~3개)
- `ideas`는 `[{"type":"...","text":"..."}]` 형식이에요. type은 촬영 릴스 / AI 영상·이미지 / 그래픽·모션 / 인스타 캐러셀 / 참여형 게시물 / 광고 소재 중에서 트렌드에 가장 잘 맞는 것을 골라요. 영상만 추천할 필요는 없어요.
- 회사 제작 방식(AI 영상, 그래픽을 모션으로 만든 콘텐츠, 캐러셀 등)도 제안에 포함하되, 거기에 끼워 맞추느라 트렌드에서 벗어나면 안 돼요. 트렌드가 먼저예요.
- 데이터(쇼핑 클릭, 성별·연령)에서 나온 인사이트를 광고 소재 제안에 연결하면 좋아요. 예: 쇼핑 클릭이 거의 늘지 않았다면 구매 유도보다 정보형 소재.
- `refs`, `series`, 숫자 필드는 그대로 둬요.
- `seasonal`이 true면 "작년 이맘때도 올랐던 키워드"라는 점을 본문에 자연스럽게 녹여요.

## 이번 주 유행 포맷 (`formats`)
- 업종과 상관없이 요즘 릴스·틱톡·쇼츠에서 유행하는 영상 구성과 챌린지를 3~5개 골라요. (예: F&B의 '손으로 화면을 가렸다 치우면 빈 테이블이 음식으로 가득 차는' 전환)
- draft.json의 formatNews(업종 무관 뉴스 기사)를 참고하고, 웹 검색으로 밈·트렌드 정리 사이트, 트렌드 뉴스레터 공개글, 기사 등 날짜가 확인되는 출처를 찾아요.
- 최근 2주 안에 유행으로 기록된 것만 실어요. 원래 더 오래된 포맷이면 "최근 다시 늘고 있다"는 근거가 있을 때만.
- 후보 포맷은 수집을 돌릴 때 Run workflow의 `formats` 칸에 쉼표로 넣어요(예: `마카롱 말먹, 색소폰 밈`). draft.json의 `formatSignals`에 최근 7일 업로드 수(recent7)와 직전 3주 주평균(priorWeeklyAvg), 최근 7일 인기 영상(top)이 들어와요.
- 각 포맷에 `why`(이번 주 트렌드라고 판단한 근거, 1문단)와 `signal`(formatSignals 값)을 넣어요. 최근 7일 업로드가 직전 주평균보다 뚜렷이 많거나 날짜가 확인되는 최근 기사가 있을 때만 싣고, 레퍼런스는 되도록 `top`의 최근 영상을 써요.
- 각 포맷: title, platforms(["릴스","틱톡","쇼츠"] 중), origin(처음 뜬 업종·분야, 출처에 있을 때만), body(무엇이고 어떻게 퍼졌는지 2문단), steps(촬영 구성 3~5단계), ideas(뷰티 브랜드 응용 제안 2개, 트렌드 ideas와 같은 형식), refs(실제 예시 영상 2~3개: url, ch, title, platform), src(출처: name, url, date)
- 참고 영상은 실제로 열리는 링크만 실어요. 확인할 수 없으면 빼요.
- 첫 번째 유튜브 참고 영상의 썸네일이 포맷 대표 이미지로 자동 표시돼요. 그러니 가장 포맷을 잘 보여주는 영상을 refs 맨 앞에 두세요.

## 이번 주 브랜드 사례 (`cases`)
- draft.json의 cases는 뉴스 검색으로 모은 기사 목록이에요. 이를 참고하고 웹 검색으로 보강해서, 지난주 날짜가 확인되는 기사·공식 자료 기반으로 3~5개를 블로그형으로 다시 써요.
- 각 사례: brand, platform(인스타그램/릴스/틱톡/유튜브), title, body(2~3문장), point(가져갈 포인트, 편집부 제안), sourceUrl, sourceName, sourceDate(YYYY-MM-DD), postUrl(있을 때만)
- 원문을 직접 열어 브랜드 이름과 날짜가 맞는지 확인한 것만 실어요. 블로그형으로 쓴 사례는 `mode` 필드를 빼요.
- 확인되는 사례가 없으면 억지로 채우지 말고 `cases`를 빈 배열로 둬요. (섹션이 자동으로 숨겨져요)

## 클라이언트 브랜드 동향 (`clients`)
- 클라이언트 목록(검색어 포함)은 `scripts/weeklip/config.json`의 clientBrands에서 관리해요. 이름이 흔한 브랜드는 keywords·news·video에 구체적인 검색어를 넣어요(예: 티젠 → 티젠 콤부차).
- **이번 주 이슈(`issues`)**: draft.json의 `newsItems`(지난주 기사)를 읽고, 필요하면 웹 검색으로 보강해서 클라이언트를 대할 때 알아 두면 좋은 소식을 브랜드마다 1~3개 적어요. 신제품 출시, 새 사업·진출, 주력 제품, 준비 중인 것, 협업·캠페인, 실적, 그리고 리콜·논란·소송 같은 안 좋은 소식도 빠짐없이 적어요.
- 형식: `[{"text":"한 문장 요약","tone":"good|bad|info","source":"매체명","url":"기사 URL","date":"YYYY-MM-DD"}]`. 기사 내용 그대로 요약하고, 추측은 쓰지 않아요. 동명의 다른 대상 기사는 빼요. 이슈가 없으면 빈 배열로 둬요.
- 브랜드 로고 파일이 준비되면 `work/weeklip/logos/브랜드명.png`로 올리고, 카드의 이니셜 칸에 잘리지 않게(object-fit: contain) 표시해요.
- 수치는 그대로 두고 손대지 않아요. 클라이언트 목록은 `scripts/weeklip/config.json`의 clientBrands에서 관리해요.
- 영상·기사는 브랜드 이름으로 검색한 결과라 동명의 다른 대상이 섞일 수 있어요. 영상 제목이 브랜드와 무관하면(예: 티젠 → 게임 선수) 그 브랜드의 `video`를 null로 바꾸고 `clientsIntro`에 이유를 밝혀요.
- 화면에는 브랜드별 문단으로 자동 표시돼요. 더 자연스럽게 다듬고 싶으면 각 브랜드에 `summary`(HTML 문단, 수치는 데이터 그대로)를, 섹션 앞에 `clientsIntro`(이번 주 전체 흐름 1~2문장)를 넣어요.

## 발행 요청을 받았을 때 (Claude 작업 메모)
요청 문구 예: "이번주 위클립 발행해줘", "위클립 이번 주 호 올려줘". 저장소: https://github.com/dylee-spec/gamecenter

1. **수집 실행**: 크롬 확장으로 https://github.com/dylee-spec/gamecenter/actions/workflows/weeklip.yml 에서 Run workflow → 초록 Run workflow. 1~2분 기다려요.
2. **데이터 읽기**: bash에서 `curl -sL https://github.com/dylee-spec/gamecenter/raw/main/work/weeklip/draft.json` 으로 읽어요. `id`가 이번 주(예: 2026-09-w5)인지, `dataRange`가 지난주인지 먼저 확인해요.
3. **글쓰기**: 위 규칙대로 trends·formats·cases·clients를 채워요. 형식과 문체는 issues.json의 `2026-09-w4` 호를 본보기로 삼아요. 트렌드 `refs`는 draft.json 값(id, ch, title, views, published)을 그대로 써요.
4. **issues.json 만들기**: 현재 issues.json을 raw 주소로 받아, 같은 id가 있으면 교체하고 없으면 배열 끝에 추가해요. 현재 호가 첫 호 앞뒤로 정렬되는지(오래된 호가 앞) 확인해요.
5. **올리기**: https://github.com/dylee-spec/gamecenter/edit/main/work/weeklip/issues.json 편집 화면에서 에디터 내용을 새 파일로 바꿔 커밋해요. 긴 내용은 gzip+base64로 나눠 sessionStorage에 옮긴 뒤 브라우저에서 풀어 CodeMirror(`.cm-content`의 cmTile→view)에 dispatch하고, 조각마다 SHA-256으로 확인해요. Commit changes... 버튼은 좌표 클릭이 가장 안정적이에요.
6. **검증**: 커밋 후 raw 주소로 다시 받아 JSON 내용이 같은지 비교하고, https://dylee-spec.github.io/gamecenter/work/weeklip/ 에서 호가 보이는지 확인해요.
7. **보고**: 이번 호에 실린 트렌드와 포맷, 빠진 섹션과 그 이유(예: 검증된 브랜드 사례 없음)를 담당자에게 한국어로 짧게 알려요.

## 발행 전 체크리스트
- [ ] 모든 숫자가 draft.json 또는 확인한 출처와 일치한다
- [ ] 광고 금지 표현이 없다
- [ ] 참고 영상 링크가 모두 실제로 열린다
- [ ] 해석 문장은 편집부 해석이라고 밝혔다
- [ ] 확인 안 된 섹션은 비웠다(억지로 채우지 않았다)
